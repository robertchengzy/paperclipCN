## 退出问题的两层原因

`useSignOut` 成功后重置账户查询，会话和 Board 权限查询随即并发刷新。旧 `CloudAccessGate` 先显示权限错误，再判断空会话，因此 `Board authentication required` 可以挡住登录跳转。

隔离浏览器还复现了另一条路径：布局设置查询被重置后，`App` 因 `streamlinedUiLoaded=false` 卸载整个认证守卫，页面停留在加载状态，直到无权限的设置请求结束重试。现在使用可选 `contentReady` 属性（默认 `true`）控制守卫内部的页面内容等待，认证判断与初始化引导保持挂载。

保留 `next` 路径与查询串、失败退出时的会话和缓存、有效会话下的访问错误、初始化引导及 Cloud `/cloud/logout` 流程。没有公共 REST API、数据库、认证协议或服务端代码变更。

## 中文审查边界

全词表检查包括 Agent/Skill、未译普通英文、旧称谓、数量范围、状态及角色用语；按组件语境审查同类项和含技术语法的例外；其中包含 53 个中英文相同且含空格的候选值，以及 173 对状态/角色词。不是对 14,797 条进行逐条完整人工重译，也不是全站浏览器验收。

- Agent/Agents → 智能体，Subagent → 子智能体，Skill/Skills → 技能，Skill(s) Studio → 技能工作室。中文以数量及所有/任意/全部等限定表达范围，保留原占位符。
- 修复组织仍称公司、产物仍称工件、Headers 缩成 Header、认证说明中的 key，以及技能分配说明主被动不清等问题。HTTP Header → 请求头；认证 key → 密钥；技能 key/slug → 标识/路径标识，按语境区分。
- Agent Skills 是格式名；skills.sh、AGENTS.md、SKILL.md、claude-agent-acp、模板变量、富文本标签、品牌及第三方正式字段名保留原文。Board 身份与看板视图保持分义；Token/Worktree/Harness/Watchdog 等专业词保留现有约定。
- 状态和角色词的不同译法不机械合并，例如任务 Idle 为等待中、智能体 Idle 为空闲，Owner 随负责人/资源所有者语境区分。
- 所有修改值的插值、富文本标签、反引号内容、上述文件名及程序标识前后对照通过。英文文件与基线逐字节一致。浏览器样例中的智能体名称和技能正文刻意包含 Agent/Skill，仍显示原文。
